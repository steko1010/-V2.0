## 1. 产品概述

### 1.1 背景与问题

显示模组（LCD/背光/盖板/FPC 等）研发与量产过程中，涉及大量四级物料（胶材、光学膜材、玻璃盖板、FPC、背光器件等）的开发、认证、稽核与选型工作。现状痛点：

1. **物料认证状态不透明**：认证资料（ROHS / REACH / MSDS / 规格书）分散在个人电脑与邮件中，缺料/过期/失效状态无法一眼看清，重复开发与超期使用风险高。
2. **选型无查重口径**：新项目立项时无法快速判断"这个物料/供应商是否已有"，造成重复认证、重复稽核。
3. **供应商与稽核信息碎片化**：供应商能力、资质、历史稽核问题与改善情况没有结构化沉淀，稽核问题趋势无法量化。
4. **项目风险与预研专项缺跟踪**：在研项目风险点、预研专项里程碑（立项 / P1 / P2 / P3）仅有线下表格，风险跟踪与责任落实缺少抓手。
5. **文档录入成本高**：供应商提供的规格书、认证报告多为 PDF / Word / Excel，需人工逐字段抄录进系统。

### 1.2 产品定位与目标

一套面向显示模组行业物料开发的**内部管理型 B/S 系统**，覆盖「物料开发认证 → 选型查重 → 供应商与稽核 → 项目风险与预研 → BOM 信息」全链路，用统一数据底座把线下表格变成可查询、可统计、可导出的在线台账。

核心目标：

| 目标 | 衡量方式 |
| --- | --- |
| 物料认证状态可视 | 物料汇总表可按 绿区/黄区/红区 筛选，看板给出三区占比与资料覆盖率 |
| 选型避免重复开发 | 提供查重接口，输入名称/型号/编码即可判断是否在库，并给出相似物料 |
| 供应商能力与稽核可追溯 | 供应商台账 + 稽核记录 + 稽核问题趋势（年度/月度） |
| 项目风险与里程碑可跟踪 | 在研项目风险清单（一行=一个风险点）+ 预研专项（立项/P1/P2/P3） |
| 录入成本下降 | 支持 Excel 批量导入；支持 PDF/DOCX/XLSX 文档自动提取字段（AI 可选） |
| 数据范围可控 | 按品类/供应商给用户授权，用户仅见其负责范围的数据 |

### 1.3 目标用户与典型场景

| 角色（业务视角） | 典型场景 |
| --- | --- |
| 物料工程师 | 新建物料、维护认证状态与资料齐套、跟踪 90 天内到期物料 |
| 选型工程师 | 新物料立项前查重、维护 AVL 候选供应商清单与三四级物料清单 |
| 供应商质量工程师（SQE） | 维护供应商能力档案、登记稽核记录、分析稽核问题趋势 |
| 项目/预研负责人 | 登记在研项目风险点与进度措施、维护预研专项里程碑 |
| 部门管理者 | 通过各模块「分析看板」了解认证、稽核、供应商、项目风险整体分布 |
| 系统管理员 | 维护用户、角色、权限、数据范围与三级品类树 |

### 1.4 版本范围（V1.0）

**本期包含**：登录与权限、物料汇总表、选型、项目（在研/预研）、稽核、BOM 信息、供应商信息、关键工艺（QCP）、品类管理、系统管理，以及批量导入导出、文档解析与 AI 提取、附件上传等通用能力。

**本期不含**（见第 9 章）：多级审批流与电子签核、消息通知/邮件提醒、外部系统（ERP/MES/PLM）对接、移动端原生 App、字段级权限、操作审计日志查询界面。

## 2. 系统形态与总体架构

### 2.1 部署形态

| 形态 | 说明 |
| --- | --- |
| 单机模式（默认） | 单个 Node 进程同时托管前端页面、`/api` 接口与 `/uploads` 附件，浏览器直连 `:3000` |
| 前后端分离 | `SERVE_STATIC=0` + `HOST=127.0.0.1`，前端静态资源交 Nginx 反向代理，后端只提供 `/api` 与 `/uploads` |
| 容器部署 | 根目录 `Dockerfile` 基于 `node:24-slim`，`npm ci` 后启动 `server.js`（云托管/容器平台） |
| Java 迁移版（并行实现） | `backend/` 为 Spring Boot 3 + MySQL 8 的同契约实现，前端产物无需改动、挂载 `/app`，接口契约与 Node 版一致 |

### 2.2 技术栈

| 层 | Node 版（默认交付形态） | Java 迁移版（可选） |
| --- | --- | --- |
| 运行时 | Node.js ≥ 22.5（推荐 24 LTS），使用内置 `node:sqlite` | JDK 17+ / Spring Boot 3 |
| 数据存储 | SQLite 单文件 `data/materials.db` | MySQL 8（`material_cert` 库，启动执行 `schema.sql`） |
| 服务端 | Express 4 + express-session | Spring Boot MVC + JdbcTemplate（无 JPA） |
| 前端 | React 18 + Vite + Zustand + React Router + ECharts（构建产物挂 `/app`） | 同左，完全复用 |
| 旧版前端 | `public/` 多页静态站点（原生 JS），与新 SPA 并存、渐进迁移 | — |
| 文档解析 | `pdf-parse` / `mammoth` / `xlsx` | 同能力 |
| 导出 | `xlsx` 生成 `.xlsx` | 自实现轻量 xlsx 写入器 |

### 2.3 无构建依赖的交付约束（仅 Node 版）

`db.js` 在 `require` 时立即执行建表与迁移，因此**修改 `db.js` 必须重启进程才生效**；新增业务字段必须同时改「建表语句 + 迁移 IIFE + 服务端字段白名单 + 前端表头/表单」，否则会出现「库里存了但前端看不见 / 导入列对不上」。

## 3. 角色与权限

### 3.1 权限模型：四层防线

| 层级 | 名称 | 机制 | 拦截点 |
| --- | --- | --- | --- |
| 第一层 | 会话准入 | `express-session`，cookie `sid`，有效期 12 小时 | 除 `/api/login`、`/api/logout` 外所有 `/api/*` 必须登录；401 时前端自动跳登录页并带 `redirect` |
| 第二层 | 功能权限 | `permissions` 代码清单 + 角色（`roles ↔ role_permissions ↔ user_roles`） | 接口声明式守卫 `requirePermission('action:edit')` 等；前端按 `page:*` 隐藏菜单、按 `action:*` 隐藏按钮 |
| 第三层 | 数据范围 | `user_category_scopes`（品类）、`user_supplier_scopes`（供应商） | 列表/统计/导出/元数据接口统一经 `scopeWhere` 注入过滤 |
| 第四层 | 特殊规则 | 管理员专属菜单、内置角色修正 | `page:admin`、`page:categories` 为管理员专属；服务启动时持续修正角色权限 |

### 3.2 权限码清单（内置）

菜单权限（`page:*`）：

| 权限码 | 显示名 | 排序 | 备注 |
| --- | --- | --- | --- |
| `page:index` | 物料汇总表 | 10 | 登录后默认落地页 |
| `page:prestudy` | 项目 | 20 | 在研项目 + 预研专项 |
| `page:selection` | 选型 | 30 | AVL 清单 + 三四级物料清单 + 看板 |
| `page:audits` | 稽核 | 40 | |
| `page:projects` | BOM信息 | 50 | |
| `page:suppliers` | 供应商信息 | 60 | |
| `page:categories` | 品类 | 65 | **管理员专属** |
| `page:qcps` | 关键工艺 | 70 | |
| `page:admin` | 系统管理 | 200 | **管理员专属** |

操作权限（`action:*`）：`action:create`（新增，100）、`action:edit`（编辑，110）、`action:delete`（删除，120）、`action:export`（导出，130）、`action:import`（导入，140）。

### 3.3 内置角色

| 角色编码 | 名称 | 权限范围 | 内置 |
| --- | --- | --- | --- |
| `admin` | 超级管理员 | 全部菜单 + 全部操作 | 是 |
| `editor` | 编辑用户 | 全部业务菜单（不含系统管理、品类）+ 全部操作 | 是 |
| `readonly` | 只读用户 | 全部业务菜单（不含系统管理、品类），无任何操作权限 | 是 |

内置角色仅在**首次初始化**时创建（`sys_flags.roles_seeded` 标记）；管理员删除内置角色后重启不会自动重建。

### 3.4 权限规则细则

1. **超级管理员（`is_super=1`）**：跳过所有权限与数据范围校验。
2. **账号 ↔ 专属角色同步**：新建用户时自动创建同名专属角色（编码=账号、名称=姓名），并授予 7 个业务菜单权限后自动分配给该用户；修改账号/姓名会同步更新该专属角色编码/名称；删除用户时若其专属角色未被其他用户使用则一并清理。
3. **品类菜单管理员专属**：任何未持有 `page:admin` 的角色不得持有 `page:categories`；创建/编辑角色时自动过滤，服务启动时也会持续回收违规授权，并为管理员级角色自动补齐。
4. **只读角色不得持有系统管理菜单**：启动时强制回收。
5. **不能删除当前登录账号**。
6. **密码策略**：当前为明文存储（`users.password`），仅限内网使用；生产部署建议前置网关或改造为哈希存储（见第 9 章）。

### 3.5 数据范围规则（`scopeWhere`）

| 场景 | 行为 |
| --- | --- |
| 用户未被授予任何品类/供应商范围（`allowAllWhenEmpty = true`） | 视为**可见全部** |
| 用户被授予品类范围 | 条件为 `category IN (授权品类) OR category = '' OR category IS NULL`（空品类记录始终可见） |
| 用户被授予供应商范围 | 条件为 `supplier IN (授权供应商)` |
| 供应商模块的品类字段 | 使用 `suppliers.material_type` 作为品类过滤字段 |
| `allowAllWhenEmpty = false` | 未授权即 `1=0`（当前业务接口均使用默认 `true`） |

> 说明：`user_purchase_group_scopes` 表已在数据结构中预留（采购组范围），V1.0 未启用。

## 4. 功能需求

### 4.1 登录与会话

| 项 | 需求 |
| --- | --- |
| 登录 | 账号 + 密码；账号不存在、密码错误或账号非「启用」状态统一返回「账号或密码错误」 |
| 会话 | 登录成功写入 session（cookie `sid`，httpOnly，sameSite=lax，12 小时） |
| 权限缓存 | 用户角色/权限/范围缓存 60 秒，避免每次请求查库 |
| 登出 | 销毁会话 |
| 会话失效 | 账号被停用或删除后，最长 60 秒内会话自动失效并返回 401 |
| 登录页 | 展示产品名与默认管理员提示（`admin / admin123`） |
| 落地页 | 登录后进入「物料汇总表」；若无该权限则进入首个可访问菜单；无任何菜单权限时停留登录页 |

### 4.2 物料汇总表（物料库）

**页面**：`/materials`，菜单名「物料汇总表」。定位：全部认证物料的唯一台账。

**筛选条件**：关键词（编码 / 名称 / 型号 / 供应商 / 制造商，模糊）、分类（品类下拉）、认证状态、供应商。

**列表字段**：勾选框、编码、物料名称、型号规格、分类、供应商、制造商、认证状态（三区徽章）、认证到期（到期徽章）、ROHS、REACH、申请人、操作。

**物料字段（完整）**：

| 字段 | 中文 | 规则 |
| --- | --- | --- |
| `code` | 编码 | 唯一；不填时自动生成 `M-<年份>-<4位序号>`（如 `M-2026-0001`） |
| `name` | 物料名称 | **必填** |
| `model` | 型号规格 | 选填 |
| `category` | 分类 | 品类下拉（数据源：三级品类的「物料中类」） |
| `supplier` | 供应商 | 供应商下拉（数据源：供应商信息表） |
| `manufacturer` | 制造商 | 选填 |
| `unit` | 单位 | 选填 |
| `status` | 认证状态 | 绿区 / 黄区 / 红区，默认黄区，非法值回落黄区 |
| `cert_expire_date` | 认证到期日 | 用于到期/临期判定 |
| `rohs` `reach` `msds` `datasheet` | ROHS / REACH / MSDS / 规格书 | 有 / 无 / 待补，默认待补 |
| `applied_by` `applied_at` | 申请人 / 申请时间 | 选填 |
| `remark` | 备注 | 选填 |
| `created_at` `updated_at` | 创建/更新时间 | 系统写入 |

**操作**：

| 操作 | 权限 | 说明 |
| --- | --- | --- |
| 查询 / 重置 | 登录即可 | 分页，默认每页 20 条 |
| 新增物料 | `action:create` | 弹窗表单（名称必填、供应商、规格型号、认证状态） |
| 编辑 | `action:edit` | 弹窗表单（同上四项） |
| 删除 | `action:delete` | 二次确认，不可恢复 |
| 批量删除 | `action:delete` | 勾选本页记录后逐条删除，返回成功条数 |
| 批量导入 | `action:import` | 接口 `/api/materials/batch`，编码重复计入错误明细 |
| 导出 | `action:export` | 导出列：编码、物料名称、型号规格、分类、供应商、制造商、认证状态、认证到期、ROHS、REACH、申请人；**支持与列表一致的筛选条件**，并按数据范围过滤 |

### 4.3 选型

**页面**：`/selection`，菜单名「选型」。含三个子页签。

#### 4.3.1 一、供应商 AVL 清单

- 数据源：供应商信息表；按「供应商 / 物料品类 / 状态 / 工厂地址 / 产品类型」列表展示。
- 支持关键词搜索、品类与状态筛选，分页展示。

#### 4.3.2 二、三四级物料清单

- 数据源：物料库（`/api/materials`）。
- 列表字段：编码、物料品类、型号规格、分类、供应商、认证状态、操作。
- 支持关键词搜索 + 品类/状态/供应商筛选，新增/编辑/删除、批量删除、批量导入、导出。

#### 4.3.3 三、分析看板

- **物料侧**（`/api/stats`）：认证状态分布（绿区/黄区/红区）、品类分布、供应商分布、资料覆盖率（ROHS/REACH/MSDS/规格书）。
- **供应商侧**（`/api/suppliers/stats`）：合作状态分布、评级分布、物料品类分布。
- 图表形式：环形图 / 横向条形图（ECharts 按需懒加载）。

#### 4.3.4 选型查重（接口已就绪）

| 项 | 需求 |
| --- | --- |
| 接口 | `POST /api/check`（`action:create`） |
| 入参 | 名称、型号、供应商、制造商、编码（至少填其一） |
| 精确匹配 | 名称 / 型号 / 供应商 / 编码任一完全一致 |
| 模糊匹配 | 名称或型号互相包含；名称会**剥离常见类别后缀**（如「贴片电阻」→「贴片」）以命中同系列物料；结果去重并排除已精确命中项 |
| 结论 | 返回 `inLibrary`（是否在库）、`tip`（提示语）、`exact`、`fuzzy`（各上限 50 条） |
| 提示语 | 在库：建议核实后再立项避免重复开发；仅在相似：建议先核对；均无：可新增立项 |
| 现状 | 后端接口完备；React 版「选型」页暂未提供查重入口（旧版 `public/select.html` 可用），列为后续迭代项 |

### 4.4 项目（在研项目 / 预研专项）

**页面**：`/prestudy`，菜单名「项目」。含三个子页签，两清单**共用同一张表**（`prestudies`）并以 `kind` 区分：

| 子页签 | `kind` | 一行含义 |
| --- | --- | --- |
| 一、在研项目 | `research` | 一个风险点 |
| 二、预研专项 | `''`（空） | 一个专项 |
| 三、分析看板 | 可选统计范围：预研专项 / 在研项目 / 全部 | — |

#### 4.4.1 一、在研项目（风险清单）

- 列表字段：序号、物料品类、供应商、项目名称、立项、P1、P2、P3、**风险**、**进度措施**、状态、责任人、操作。
- 搜索范围：项目名称 / 风险 / 进度措施 / 供应商 / 责任人。
- 支持新增、编辑、删除、批量删除、批量导入（导入到当前所在清单）、导出。

#### 4.4.2 二、预研专项

- 列表字段：序号、物料品类、供应商、专项名称、立项、P1、P2、P3、风险、状态、责任人、操作。
- 字段：物料品类、供应商、专项名称（**必填**）、风险、进度、立项、P1、P2、P3、状态、责任人。
- 里程碑字段为**文本**（如「26/7/30」「26/11/6 装机」），不做日期格式化，兼容各种书写习惯。

#### 4.4.3 三、分析看板

`/api/prestudies/stats` 输出：

- 总量、按品类、按状态、按里程碑（立项 / P1 / P2 / P3 各自计数）、按责任人（Top10）、按供应商（Top10）；
- 按项目统计**问题个数**（一行一个风险点，逐条计数，不做项目级合并）；
- `issueTotal`（风险点总数）、`projectTotal`（去重项目数）、最近 8 条记录。

#### 4.4.4 文档导入

支持上传 PDF / DOCX / XLSX / TXT 等原始文件，自动提取「品类 / 专项名称 / 风险 / 进度 / 状态 / 责任人」；提取结果经前端弹窗确认后落库，来源标记为「文档导入」。

### 4.5 稽核

## 5. 业务规则汇总

### 5.1 认证状态三区（核心业务规则）

| 状态 | 业务含义 | 徽章色 |
| --- | --- | --- |
| 绿区 | 认证有效 | 绿 |
| 黄区 | 认证流程中 / 需关注（默认值） | 黄 |
| 红区 | 已过期 / 失效 / 淘汰（需尽快处理） | 红 |

历史 6 态到三区的迁移口径（老库启动自动执行）：

| 原状态 | 新状态 |
| --- | --- |
| 已认证 + 到期日 < 今天 | 红区 |
| 已认证（未过期） | 绿区 |
| 开发中 / 送样测试 / 认证中 | 黄区 |
| 已失效 / 已淘汰 | 红区 |

看板口径：

- **绿区数** = 认证有效数（`certOk`）；
- **黄区数** = 认证流程中（`inProgress`）；
- **红区列表** = 已过期/失效/淘汰，按到期日排序（无到期日排最后），最多 20 条；
- **临期预警** = 绿区且到期日在 `[今天, 今天+90天]`，按到期日升序，最多 20 条；
- **资料覆盖率** = 某资料项状态为「有」的物料数 ÷ 物料总数（百分比取整）。

> 状态目前为**人工维护**，系统不做"到期日自动翻红"的定时任务；到期/临期通过看板与徽章提示，需人工改状态（见第 10 章规划）。

### 5.2 资料齐套

四类资料：ROHS、REACH、MSDS、规格书；状态枚举：有 / 无 / 待补（默认待补）。资料缺失可通过「资料覆盖率」看板与列表徽章识别。

### 5.3 物料编码

未填编码时自动生成 `M-<年份>-<4位序号>`：取当年已有编码的最大序号 +1，不足 4 位左补 0。编码全局唯一，重复导入会报「编码已存在」。

### 5.4 分页与筛选口径

| 模块 | 默认每页 | 上限 | 备注 |
| --- | --- | --- | --- |
| 物料（含选型物料清单） | 20 | 100 | |
| BOM 信息 | 5 | 100 | |
| 预研专项 / 在研项目 | 10 | 100 | |
| 稽核 | 10 | 100 | |
| QCP | 10 | 100 | |
| 供应商 | 不分页 | 500 条 | |

所有列表默认按 `id` 升序（看板「最近」列表按 `id` 降序）。

### 5.5 统计口径注意事项

1. **预研/在研按 `kind` 隔离**：列表、导出、看板默认只看当前清单；看板可通过 `kind=prestudy|research|all` 切换统计范围。
2. **风险点不等于项目**：`issueTotal` 统计风险点行数，`projectTotal` 按项目名称去重计数。
3. **稽核问题个数为估算值**：由稽核内容文本按编号/换行推算，非结构化字段统计。
4. **统计均遵循数据范围**：非超管用户看到的看板数字仅含其授权品类/供应商范围。

| `sys_flags` | 系统标记（如 `roles_seeded`） |

### 6.3 迁移约束（老库升级）

所有新增字段必须提供 `PRAGMA table_info` 检测 + `ALTER TABLE ... ADD COLUMN` 的迁移逻辑（字段默认 `TEXT DEFAULT ''`），保证老库启动即平滑升级；`prestudies.kind` 首次加列时须把存量记录统一归为 `research`。

## 7. 接口契约（摘要）

### 7.1 通用约定

- 前缀 `/api`，除登录/登出外均需登录；返回 JSON，错误体为 `{ "message": "..." }`。
- 字段命名 `snake_case`，与数据库列一致。
- 列表统一返回 `{ total, page, pageSize, items }`（物料另有 `page`/`pageSize`）；预研/稽核/QCP 额外返回 `pages`。
- 批量导入返回 `{ success, skipped, errors }`（错误项含行号与原因）。

## 9. 边界与不做的事

1. **无审批流**：物料认证状态由人工直接修改，系统不提供多级审批、签核、驳回、留痕。
2. **无消息通知**：临期/到期不做邮件或站内提醒，依赖人工查看看板。
3. **无字段级权限**：数据范围为记录级（品类/供应商），不支持"某字段仅管理员可见"。
4. **无操作审计日志界面**：仅保留 `created_at`/`updated_at`，不支持操作人追溯。
5. **密码为明文存储**：仅适用于内网可信环境。
6. **无外部系统集成**：不与 ERP / MES / PLM / SRM 打通，数据以 Excel 导入导出为交换方式。
7. **无并发编辑锁**：多人同时编辑同一条记录时后写覆盖先写。
8. **AI 提取依赖外网与密钥**：未配置时功能降级为关键词规则提取，准确率有限。

## 11. 验收标准（V1.0 基线）

1. 使用 `admin / admin123` 可登录，登录后默认进入物料汇总表；未登录访问任意页面跳转登录页并在登录后回到原页面。
2. 新建只读角色用户：仅可见 7 个业务菜单，页面上无任何新增/编辑/删除/导入/导出按钮，直接调用写接口返回 403。
3. 给用户授予品类范围 A：其在物料、BOM、预研、稽核、QCP 页面及对应导出、看板中，只能看到品类为 A（或品类为空）的数据。
4. 新增物料不填编码，系统生成 `M-<当年>-0001` 形式的唯一编码；重复编码导入返回「编码已存在」并计入错误明细。
5. 物料列表可按关键词、分类、认证状态、供应商筛选，分页每页 20 条；导出的 Excel 内容与当前筛选结果一致。
6. 在研项目与预研专项数据互不串页；看板可按「预研专项 / 在研项目 / 全部」切换统计范围，且 `issueTotal` 等于风险点行数、`projectTotal` 等于去重项目数。
7. 稽核看板可按年度/月度切换问题趋势，曲线对象为问题总量 Top6 供应商，月度曲线连续且空月计 0。
8. 上传一个 PDF 规格书到 BOM 信息页：能解析出文本并返回提取字段（未配置 AI 密钥时走规则提取），确认后才落库，来源显示「文档导入」。
9. 上传 Excel 到 BOM 信息页：能自动识别含说明行的表头，预览确认后批量入库；内容完全重复的行被跳过并计入 `skipped`，库中已有数据不被覆盖或删除。
10. 供应商信息新增/删除后，各页面「供应商下拉」自动同步；品类管理新增中类后，各页面「品类下拉」自动同步。
11. 修改 `db.js` 新增一个物料字段并重启：老库启动自动补列，接口可读写，前端可见（四处同步验证通过）。
12. `node --check server.js db.js` 通过；单机模式下 `/`（旧版页面）与 `/app`（SPA）均可访问，`/api` 接口正常，`/uploads` 附件可访问。
